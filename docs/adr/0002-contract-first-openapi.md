# ADR-0002: Contract-first — OpenAPI 3.1 + RFC 9457
**الحالة:** مقبول (D-03 بانتظار تأكيد نهائي من الفريق)

## السياق
فريقان يعملان بالتوازي (Backend و Frontend). R1-A3/A4 يطلبان أخطاء موحدة وتوثيقاً قابلاً للتجربة.

## القرار
- `contracts/openapi/openapi.yaml` (OpenAPI 3.1) يُكتب **قبل** الكود ويملكه الـ Lead.
- Laravel: كل اختبار Feature يتحقق من مطابقة الاستجابة للعقد؛ واختبار يضمن تطابق قائمة الـ routes مع العقد.
- React: الأنواع مولّدة (`openapi-typescript`) والعميل `openapi-fetch` ⇒ أي انحراف = خطأ ترجمة. MSW للتطوير قبل جاهزية الـ API.
- الأخطاء: RFC 9457 `application/problem+json` + `code` ثابت + `trace_id`.
- Swagger UI يقرأ نفس الملف.

## البدائل المرفوضة
- **Code-first (Scramble):** ممتاز للتوثيق، لكنه يجعل العقد نتيجة للكود ⇒ الواجهة تنتظر الـ backend، ولا يوجد مصدر حقيقة يُراجَع قبل التنفيذ. (يمكن إضافته لاحقاً كأداة مقارنة.)
- **Postman collection فقط:** لا يولّد أنواعاً ولا يتحقق آلياً.
- **صيغة أخطاء مخصصة:** إعادة اختراع لمعيار موجود.

## العواقب
+ تطوير متوازٍ حقيقي، انحراف مستحيل دون فشل CI. − تغيير العقد يمر بمراجعة (مقصود)؛ كتابة YAML يدوياً تحتاج Redocly lint.
