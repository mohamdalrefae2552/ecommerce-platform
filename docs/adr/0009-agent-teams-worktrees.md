# ADR-0009: التنفيذ بـ Claude Code Agent Teams + worktree لكل وكيل
**الحالة:** مقبول

## السياق
الفريق يريد تنفيذاً متوازياً منظماً كفريقين متعاونين. Agent Teams ميزة تجريبية (Claude Code ≥ v2.1.32، `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`) بقيود موثقة: لا استئناف للأعضاء داخل الجلسة بعد `/resume`، قد يتأخر تحديث حالة المهام، تعديل نفس الملف من عضوين يكتب فوق بعضه، العضو لا يطبّق حقل `skills` من تعريف الـ subagent (يحمّل skills المشروع بنفسه).

## القرار
- Lead + 4 أعضاء (ضمن التوصية الرسمية 3–5): فريق Backend (laravel, spring) وفريق Frontend & Quality (react, qa).
- تعريفات الأدوار في `.claude/agents/*.md` وتُستدعى بالاسم عند الإطلاق.
- ملكية مجلدات صارمة + worktree مستقل لكل منفّذ على فرع مهمته.
- بوابات جودة بالـ hooks: `TaskCompleted` (تحقق المكوّن)، `TeammateIdle` (لا خمول مع تغييرات غير مُلتزمة)، `PostToolUse` (تنسيق)، `PreToolUse` (حماية المولَّد والأسرار).
- مراجعة مستقلة بـ subagent `code-reviewer` لم يرَ التنفيذ.
- الدفعات قصيرة (5–6 مهام لكل عضو) والإنسان يراقب ويوجّه.

## البدائل المرفوضة
- **جلسة واحدة:** أبطأ وسياق مزدحم.
- **Subagents فقط:** لا تواصل مباشر بين Laravel و Spring حول دلالات gRPC.
- **جلسات يدوية منفصلة بلا تنسيق:** تفقد قائمة المهام المشتركة.

## العواقب
+ توازي حقيقي مع حدود واضحة. − استهلاك tokens أعلى؛ ميزة تجريبية ⇒ إن ساءت: نعود لجلسة واحدة + subagents بنفس الملفات دون تغيير (التعريفات تعمل كـ subagents أيضاً).
