# ADR-0012: مجلد عمل واحد لكل الوكلاء (يستبدل قسم الـ worktrees في ADR-0009)
**الحالة:** مقبول (قرار الإنسان، 2026-11-02)

## السياق
ADR-0009 وضع كل وكيل في git worktree خاص (`../<repo>-wt/<name>`) لمنع الكتابة فوق ملفات بعضهم. عملياً على جهاز الفريق:
- المجلدات الإضافية بجانب المشروع كانت مربكة للإنسان ("ما هذا المجلد؟").
- الملكية مقسّمة أصلاً بالمجلد (`backend/api` ← laravel، `backend/inventory` ← spring، `frontend` ← react، `tests/` ← qa، الباقي ← Lead)، فلا يوجد ملف يكتبه وكيلان.
- طلب الإنسان صراحةً أن يعمل الجميع في مجلد المشروع نفسه.

## القرار
- كل الوكلاء يعملون في **`C:\dev\ecommerce-platform`** مباشرة (مجلد واحد، نسخة git واحدة).
- **فرع واحد لكل دفعة** (مثلاً `chore/p0-platform` للمرحلة 0-ب، `feat/r1-…` لدفعات المتطلب 1)، وكل وكيل يضيف commits على نفس الفرع.
- **commit لكل مهمة** بصيغة Conventional Commits، و**كل وكيل يُضيف ملفات نطاقه فقط**: `git add backend/api` (مثلاً) — **ممنوع** `git add -A` أو `git add .` أو `git commit -a`، كي لا يلتقط ملفات وكيل آخر غير منتهية.
- إن فشل commit بسبب `index.lock` (commit متزامن من وكيل آخر): انتظر ثوانٍ وأعد المحاولة، لا تحذف القفل.
- `make wt` / `make wt-rm` تبقى في الـ Makefile للحاجة (تجارب معزولة) لكنها لم تعد سير العمل الافتراضي.

## البدائل المرفوضة
- **worktree لكل وكيل (ADR-0009):** يعمل، لكنه أربك الإنسان ولا يضيف أماناً حقيقياً هنا لأن الملكية مقسّمة بالمجلدات.
- **worktrees داخل مجلد مخفي في المشروع:** يبقي التعقيد نفسه.

## العواقب
+ مجلد واحد واضح؛ `make up` و E2E تعمل مباشرة على عمل الجميع دون دمج فروع.
+ لا انتظار لدمج PR قبل أن يرى وكيلٌ عمل زميله (مثلاً الواجهة ترى الـ API فوراً).
− عدد PRs أقل: PR لكل دفعة بدل PR لكل مكوّن. لتحقيق W-2 (لكل عضو بشري PR في كل متطلب) تُقسَّم الدفعات بين العضوين.
− الـ commit سيُنسب لهوية git الحالية على الجهاز؛ لا هوية منفصلة لكل وكيل.
− hooks `TeammateIdle` و `TaskCompleted` تفحص الـ worktrees المرتبطة فقط؛ في المجلد الرئيسي يتحقق الـ Lead بنفسه (`make verify-<component>`) قبل قبول أي مهمة.
