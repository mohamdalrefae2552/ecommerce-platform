# ADR-0006: Saga بالتعويض + journal + مصالحة
**الحالة:** مقبول

## السياق
R2-F1: لا يُحفظ الطلب إلا بعد موافقة المستودع. R2-E1: فشل الحفظ بعد الحجز ⇒ إرجاع الكمية. R2-E2: مهل. العقد بثلاث عمليات (لا Confirm/2PC). العمليات عبر الشبكة قد تنجح دون أن نعرف.

## القرار
- Orchestration saga داخل `CreateOrder`: journal `PENDING` مُثبَّت قبل النداء ⇒ Reserve ⇒ معاملة الطلب ⇒ عند أي فشل أو نتيجة مجهولة: Release (idempotent).
- tombstone في المستودع يغلق سباق Release-قبل-Reserve.
- `inventory:reconcile` كل دقيقة يعالج `PENDING` اليتيمة و `RELEASE_PENDING`.
- reservation_id جديد لكل محاولة؛ Idempotency-Key على مستوى الطلب.

## البدائل المرفوضة
- **2PC/XA:** غير متاح عبر gRPC ولا مرغوب.
- **حفظ الطلب `pending` ثم الحجز:** يخالف R2-F1 حرفياً.
- **TTL على الحجوزات في المستودع:** بلا RPC تأكيد سيُسقط حجوزات طلبات ناجحة.
- **Outbox + broker:** هذا المتطلب 4؛ الـ journal الحالي قابل للتطور إليه.

## العواقب
+ لا تسرّب مخزون دائم، كل حالة فشل لها مسار ومُختبرة. − اتساق نهائي (eventual) للحجوزات اليتيمة خلال ≤ ~3 دقائق في أسوأ حالة نادرة (موثّق).
