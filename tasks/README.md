## صيغة المهمة
```
### <ID> · <العنوان>
- المالك: <agent> · العضو: <A|B> · الفرع: <branch> · يعتمد على: <IDs>
- النطاق (الملفات): …
- الخطوات: …
- معايير القبول: (كل بند قابل للتحقق بأمر أو اختبار)
- التحقق: <أوامر>
```
- **المعرّف:** `P<phase>-<OWNER>-<NN>`؛ OWNER ∈ `LEAD, API, INV, WEB, QA`.
- **المالك** = الوكيل المنفّذ. **العضو** = الإنسان صاحب الـ PR والـ commits (انظر docs/07 §6).
- المهام التي تحمل نفس **الفرع** تُجمع في PR واحد.

## كيف يحوّل الـ Lead الملف إلى قائمة مهام مشتركة
لكل مهمة: `TaskCreate` بالعنوان `<ID> · <العنوان>` والوصف = النطاق + معايير القبول + التحقق، ثم `addBlockedBy` حسب "يعتمد على". الأعضاء لا يأخذون مهمة blocked.

## قواعد التنفيذ لكل عضو
1. اقرأ المهمة كاملة + المستندات المشار إليها. إن كان أي معيار غامضاً ⇒ `[QUESTION]` للـ Lead قبل كتابة كود.
2. للمنطق الحرج: اكتب الاختبار الفاشل أولاً.
3. نفّذ ضمن نطاق ملفاتك فقط، في الـ worktree المعطى.
4. `make verify-<component>` أخضر ⇒ commit ⇒ علّم المهمة completed (الـ hook سيعيد التحقق ويمنع الإغلاق إن فشل).
5. أرسل `[HANDOFF]` لمن يعتمد عليك.
